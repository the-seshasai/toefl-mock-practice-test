# Decisions

Ambiguities resolved in favor of the most faithful-to-real-TOEFL option.

- **D-01 Spec deviations from the baseline prompt.** Speaking = 7 Listen-and-Repeat + 4 Interview questions (11 items). Writing = 10 Build a Sentence + 1 Email + 1 Academic Discussion. Listening Announcement and Conversation counts follow the ETS blueprint ranges. Source: ETS 2026 blueprint PDF.
- **D-02 Scoring.** Overall = average of four sections rounded to nearest 0.5 (ETS wording), not just "average".
- **D-03 Reading stage split.** ETS does not publish router/stage item counts. We use router ≈ half the items, second stage lower/upper, capped at 50 items / ~30 min.
- **D-04 Per-task timers inside a section.** ETS publishes section times only; per-task splits (e.g. Build a Sentence ≈ 35 s each) are our estimates.
- **D-05 Passage lengths.** Blueprint says spec texts reach ~200 words; real practice passages are longer. Advanced Reading passages may exceed 200 words.
- **D-06 Band estimate.** Bands are `1 + (ceiling - 1) * fraction_correct`, rounded half-up to 0.5, where the ceiling is the best band reachable at the chosen level: Beginner 3.5, Intermediate 5.0, Advanced 6.0. ETS's IRT mapping is not public; this is a transparent estimate.
- **D-07 Build a Sentence uniqueness.** One defensible ordering is enforced by: no duplicate chunks, punctuation only on the final chunk, <=4 words per chunk, and an LLM-supplied `acceptable_orders` list (validated as permutations, max 3). Scoring accepts the answer or any listed alternative, case-insensitively.
- **D-08 Writing timers.** Server-side per-task clocks (Build a Sentence 6 min, Email 7, Discussion 10 = 23 min). Expired tasks are auto-advanced by the server with a 3 s grace; the next task's clock starts at the previous deadline so lapsed time is not refunded. Within Build a Sentence the user may move between sentences; once the task ends it is locked.
- **D-09 Fallback bank.** Leftover generated items are reused first (never served before), then new generation, then a small hand-written seed bank (10 Build a Sentence, 3 email, 3 discussion). If seeds run out they are reused with a visible warning rather than blocking the exam.
- **D-10 Scoring failures.** If the LLM fails while scoring, the section becomes `scoring_failed` (no band shown) and Results offers a retry; answers are never lost.
- **D-11 Reading structure (until adaptive routing in milestone 7).** One linear pass worth ~50 scored points: Complete the Words 3 paragraphs x 10 blanks (7 min), Read in Daily Life 3 texts x 2-3 questions (8 min), Read an Academic Passage 2 passages x 5-6 questions (15 min) = 30 min. Each task is its own server-timed stage (same engine as Writing); within a task the user can move between paragraphs/texts/passages, but cannot return after the task ends. ETS does not publish the router/second-stage item split (see D-03); milestone 7 will re-split these into a router module plus an easier or harder second module.
- **D-12 Complete the Words mechanics.** The LLM only writes the paragraph and picks 10 predictable words (none from the intact first sentence, no neighbors, distinct, >=3 letters). Code hides the second half of each word (first ceil(len/2) letters stay), builds the render segments, and scores 1 point per blank, case-insensitive. Because several words can fit a fragment, answers are matched to the intended word only.
- **D-13 Multiple-choice integrity.** Exactly one keyed option (schema: 4 options, answer index 0-3), distinct options, no "all/none of the above", question kinds from a fixed list with a minimum variety per item, vocabulary questions must quote a word present in the text. Options are shuffled in code (LLMs bias the key toward A/B) and the answer index is re-keyed.
- **D-14 Word-count tolerance.** Validators enforce the full range from the difficulty table, but prompts aim at the middle 60% of that range because LLMs miss word counts by 10-15%; this cut rejected generations sharply.
- **D-15 Parallel generation.** The tasks of a section are generated concurrently (one DB session per thread, SQLite in WAL mode); Advanced Reading went from 153 s to 75 s.
- **D-16 Listening structure (until adaptive routing in milestone 7).** One linear pass: 16 Listen-and-Choose items (6 min), 4 conversations (7 min), 3 announcements (5 min), 3 academic talks (11 min) = 29 min and roughly 46-50 scored questions. Audio time counts inside each task's timer. In exam mode items are forward-only (no Previous, questions appear only after the clip finishes); practice mode allows free navigation and replay. Milestone 7 re-splits this into a router plus an easier or harder second module (see D-03).
- **D-17 Voices and audio.** Piper `medium` voices: en_US-ryan (male), en_US-amy (female), en_GB-alba (female), en_GB-northern_english_male (male). Piper has no Australian English voice, so accents are US and UK only (ETS also uses Australian). Speakers get voices by the gender the LLM assigns, distinct per speaker, picked at audio-build time (so seeds and generation never need TTS). Speech rate follows difficulty via Piper `length_scale` (Beginner 1.15, Intermediate 1.0, Advanced 0.92). Only one voice model is held in memory at a time (8 GB machine); synthesis is grouped by voice so each model loads once per exam. Audio is one WAV per item (speakers joined with a 0.45 s pause), cached under `data/audio/` by a hash of voice, text and rate (~22 MB per exam); real-time factor on this CPU is ~0.05.
- **D-18 Play-once enforcement.** Enforced on the server, not just the UI: in exam mode the audio endpoint records the first fetch and refuses later ones (HTTP 403) after an 8 s retry window that tolerates a dropped or duplicated request. The browser fetches the whole clip once and plays it from memory, so one fetch equals one play; there is no seek or replay control. Refreshing mid-clip counts as played (the page then shows the questions). Audio of a task other than the current one is refused, and clips open up for review once the section ends. Practice mode has no limit.
- **D-19 Generation limits.** At most 3 tasks generate in parallel (each LLM call is a separate `claude -p` process; measured peak RAM during a Listening exam was ~6.7 GB of 7.7 GB). If the fallback bank has fewer seeds than an exam needs (Listening needs 16 reply items, the bank has 6), seeds are cycled with a visible warning rather than blocking the exam.
- **D-20 Speaking structure.** Listen and Repeat: 7 sentences (3 min stage) spread across the level's length range and presented shortest to longest, as on the real test; Take an Interview: one topic with 4 questions that progress from factual to hypothetical (5 min stage). 8 min total, 55 points (7 x 5 + 4 x 5 + ... = 11 responses x 5). Per-response windows are our estimates (ETS publishes none): repeat = 6 s + 0.45-0.6 s per word (8-30 s, no prep); interview = 10 s preparation then 45 s. Interview questions are audio-only (no text on screen); an interview is one Response with four recordings, so its answer is `{parts: {0..3}}`.
- **D-21 Speech-to-text.** `faster-whisper` 1.2.1 with the English-only `base.en` model, int8 on CPU, VAD on, word timestamps on. Measured about 0.1x real time (5 s of speech in ~0.5 s) and ~600 MB peak RAM. The model is freed after every scoring job (reload ~0.3 s). `av` is pinned to 14.2.0: faster-whisper 1.2.1 calls `av.open(metadata_errors=...)`, which `av` 19 removed, and `av` 14.4+ has no prebuilt wheel for Python 3.12.
- **D-22 Speaking scoring.** Listen and Repeat is scored by code, not an LLM: the transcript is aligned to the target (difflib), accuracy = matched words / max(target, heard), and the score comes from thresholds in the versioned rubric file `speaking_repeat.v1.txt` (>=0.95 -> 5, 0.85 -> 4, 0.70 -> 3, 0.50 -> 2, 0.25 -> 1). Differences are reported as missing / extra / changed words. Delivery measures (words per minute, long pauses, recognizer confidence) are reported but do not change the repeat score. Take an Interview sends all four transcripts plus delivery statistics in ONE LLM call using `speaking_interview.v1.txt`; unrecorded or near-empty answers score 0 without an LLM call. Whisper's recognition errors (e.g. "lab" heard as "lap") can cost a point, so repeat scores are estimates.
- **D-23 Recording.** The browser records with MediaRecorder (opus in webm; mp4 on Safari), uploads each response immediately as raw bytes, and the server stores it under `data/recordings/<attempt>/<response>_<part>.<ext>` (<=10 MB, duration checked against the response window + 5 s). Exam mode: one attempt per response and no playback until the section ends; practice mode: re-record and play back at any time. Refreshing in the middle of a recording loses that recording (the clip is only uploaded when it ends); the question audio counts as played and the next attempt goes straight to preparation/recording.
- **D-24 History.** `GET /api/history` lists attempts that have at least one scored (or scoring-failed) section, newest first; attempts abandoned before scoring are hidden. The History page plots every section band plus the overall band (full tests only) over attempt order on a fixed 1–6 axis, with a table linking to each Results page. The Setup screen offers Full test (Reading → Listening → Writing → Speaking, no break).
- **D-25 Adaptive structure (replaces the linear Reading/Listening of D-11 and D-16).** Reading and Listening are two-stage adaptive in section and full-test mode (single-task mode stays linear). Module 1 (router) runs at the level chosen on the Setup page; Module 2 is one level easier or harder (clamped at Beginner/Advanced). Sizes follow the ETS blueprint times: Reading router 21 min + Module 2 9 min; Listening router 18 min + Module 2 of 7 min (easier) or 11 min (harder). Reading router = 2 Complete-the-Words paragraphs, 2 daily-life texts, 1 passage (about 29-31 points); Module 2 = 1 of each. Listening router = 10 reply items, 3 conversations, 2 announcements, 2 talks; Module 2 = 6 reply items and 1 of each other task. Routing rule: router points / router maximum >= 0.60 goes to the harder module (ETS does not publish its IRT cut scores; this is a transparent heuristic, `spec.ROUTE_UP_THRESHOLD`).
- **D-26 Adaptive band formula.** Each module's fraction correct is mapped into a band interval set by its role, then modules are combined by point weight and rounded half-up to 0.5. Router/easier module: [1, ceiling(level)]. Harder module: [ceiling(level below), ceiling(level)], so being routed up never costs you (acing Intermediate and failing the Advanced module still gives 5.0). Ceilings: Beginner 3.5, Intermediate 5.0, Advanced 6.0. Non-adaptive stages (Writing, Speaking, single tasks) keep the linear [1, ceiling] mapping.
- **D-27 Pre-generation and waiting.** The router is generated up front; both possible Module 2s are generated in the background while the user takes Module 1, and the unused one returns to the item bank (its generated items become unserved again). State written by the generation job lives in its own column (`gen`) so it can never overwrite a user's timer state. If the user finishes Module 1 first, the section shows "Preparing Module 2" with the clock not running, and the job opens the module the moment it is ready; if a module cannot be generated the other is used (marked `fallback`), and only if neither exists does the section fail. Module 2's clock starts when it opens, or at the router's deadline if the router timed out (the strict clock of D-08).
- **D-28 Full test.** Sections are generated one after another in the background in exam order (Reading first, so the wait before the exam starts stays short) and a section cannot start until the previous one is submitted; scoring of a finished section runs while the next one is taken. A section that fails to generate (for example missing Piper voices) does not block the others. The overall band is the average of the four section bands rounded to the nearest half band (D-02) and is stored on the attempt. There is no break between sections, as on the real test.
- **D-29 Difficulty tuning (measured, `python -m app.tools.difficulty_report --sample N`).** The tool generates items at every level and reports words, words per sentence and Flesch-Kincaid grade. Findings with the LLM: word counts rise with level for every task; Academic Passage readability did not (Beginner 10.4, Intermediate 13.1, Advanced 12.9 against ETS's medium 7.4-10.5). Fix: an enforced FK range per level (Beginner <= 9.5, Intermediate 7.0-12.5, Advanced 12.0-20.0) plus a sentence-length target in the prompt; re-sampling gave 7.8 / 11.1 / 14.1. FK is not meaningful for dialogue or menus (conversations scored about 4 at every level, menus are telegraphic), so for those the levels differ by length, speech rate and question depth; `test_difficulty_tables_increase_with_level` guards that table ranges never shrink as the level rises.
- **D-30 Weak-spot ranking.** Each task type gets an estimated band per attempt from the points earned in each (stage, level) group, using the same level-aware intervals as section bands (D-26), so 70% on Advanced items counts for more than 70% on Beginner items. Attempts are combined with a recency weight (each older attempt counts 80% as much as the next newer one) and the weakest bands rank first (ties: lower accuracy, then name). The trend is the latest attempt's band minus the mean of up to three earlier ones. Only fully scored sections count; unscored and scoring-failed sections are ignored. Single-task and weak-spot attempts feed the per-task statistics but not the per-section summaries or the trend chart, because a one-task "section band" is not comparable with a whole section. The common error categories (grammar, vocabulary, organization, task fulfillment, delivery) are counted from Writing and Interview feedback over the last 10 attempts.
- **D-31 Practice my weak spots.** `POST /api/practice/weak-spots` takes the N weakest task types (1-5, default 3) and creates an attempt of mode `weak`: one non-adaptive section per section that contains a chosen task, in official section order and official task order, with the usual single-task set sizes and timers. The level defaults to the latest scored attempt's level and can be overridden; the mode defaults to practice (timers off, replay allowed). The same exam-order rule applies, so a multi-section drill starts with its first section. It needs at least one scored attempt and returns 400 otherwise.
